# Session 08 — 2026-08-07 — Parity Slice A: groundedness evaluation (ADR-0067, migration 0079)

Append-only. Never edited retroactively.

## What was asked for

Build **Slice A** of [COMPETITIVE_PARITY_PLAN.md](../../docs/product/COMPETITIVE_PARITY_PLAN.md) §1
— groundedness / hallucination evaluation, parity targets Langfuse, Braintrust, Arize Phoenix and
Ragas — as one ADR and one migration, extending ADR-0044's harness rather than rebuilding it.

The brief named the honesty line as the most important requirement in it, and it is worth restating
because everything below is organised around it:

> A metric that needs a model MUST refuse honestly when no provider is configured. It must NEVER
> silently degrade to a lexical proxy while reporting under the same metric name.

## What the gap actually was

The verified finding held: nothing in the codebase measured whether an answer was **supported by its
context**. But the more useful discovery was *why it could not have been added by configuration*:
`eval_cases` had nowhere to put the context. Groundedness is a relation between an answer and the
material it was supposed to rest on, so without that column every one of these metrics is undefined.
That made the migration the load-bearing part, not an afterthought.

## Decisions worth remembering

**1. Context is an ARRAY, not a blob.** Chunk boundaries are the metric. A claim whose evidence has
to be stitched out of fragments of three unrelated documents is precisely the fabrication a
groundedness metric exists to catch, and a concatenated blob scores it as fully supported. The scorer
matches each claim against the **single best chunk** for the same reason, and there is a test that
constructs exactly such a stitched claim and asserts it is refused.

**2. The prompt framing was deliberately kept minimal.** The obvious move is to prepend "answer only
from the context; say so if it is silent". Rejected: it would make every score partly a measurement
of an instruction *we* wrote rather than of the agent under test, and an injected abstention
instruction would systematically trip `answer_relevance`'s non-committal detector — silently coupling
two metrics that must stay independent. Chunks are numbered, the question is restated, nothing else.

**3. The tokenizer was HOISTED, not copied.** The brief said to check `training-provider`'s TF-IDF
primitives before writing a third tokenizer. They were genuinely appropriate. Importing *upward*
would have dragged the vendor SDKs into `@regulait/shared`, so the primitives moved down into
`packages/shared/src/text.ts` and training-provider now imports and re-exports them. One tokenizer,
correct dependency direction, and its 58 tests were untouched.

**4. `DETERMINISTIC_SCORER_KINDS` was reversed from exclusion to enumeration.** ADR-0044 had
`filter(k => k !== "llm_as_judge")`, correct with one judged kind. With three it is a hazard: the
*default* classification for any future kind becomes "free, offline, non-degrading". Now
`JUDGE_BACKED_SCORER_KINDS` is explicit and the deterministic set derives from it, so the dangerous
classification is the one you must opt into.

**5. The refusal is placed before the `eval_runs` INSERT, not after.** That is what lets the suite
assert not merely a 422 but that **no run row, no result row and not one dispatched token** exist.
A refusal that left a half-scored run behind would still leave something a later reader could cite.

## The one thing that went wrong, and what was done about it

Making all three judge-backed kinds refuse broke an existing ADR-0044 test:

> `an llm_as_judge case with NO judge configured FAILS loudly rather than passing`

That test defends an **accepted** behaviour — an unjudgeable case scores 0 with
`error: 'no_judge_configured'`. Two honest observations pulled in opposite directions:

- That behaviour is genuinely loud. It is not a silent pass and it is not a lexical proxy wearing a
  judged metric's name, which is the specific dishonesty this slice exists to prevent.
- It is nonetheless the **weaker** posture. A zero meaning *"we could not measure this"* is
  aggregated into `meanScore`, compared against a baseline, and read by a gate as though it meant
  *"the agent answered badly"* — and the run is stored, so it can be cited as model-card evidence.

**The change was not made.** Unifying them would be the better end state, but doing it would change
an accepted ADR's contract from inside a slice about a different metric — the unilateral scope creep
this project's history warns about. `JUDGE_REFUSING_SCORER_KINDS` now names the two new kinds
explicitly, a test pins the boundary in **both** directions so it cannot drift by accident, and the
ADR, the index row and STATE.md all disclose the asymmetry with its reasoning. Unification is named
follow-up for the owner to decide.

Worth recording because the tempting move was the other one: silently widen the refusal, update the
old test, and let the ADR imply it had always been that way.

## A second small hole found while finishing

The SPA's eval page renders its scorer dropdowns from `GET /v1/evals/scorers`, so the six new kinds
appeared in the browser **automatically** — and every attempt to author one would have 422'd, because
the case form had no context input. Adding a context textarea (blank-line-separated chunks) and an
in-prompt checkbox was a ten-line change and closed it. What still does not exist is any groundedness
*reporting* view; that is disclosed rather than implied away.

## What is NOT true, in one place

- The judge-backed metrics' **judgment** is unverified. No provider is connected. The refusal, the
  prompt construction, the strict parser, the per-claim storage and the `model-judged` labelling are
  all proved; whether a real model judges entailment well is not.
- The lexical metrics cannot see negation flips or swapped attribution, and score a synonym-only
  paraphrase as unsupported. **Those three limitations are themselves tests**, so they cannot quietly
  become untrue without someone deliberately inverting an assertion.
- `context_precision` is retrieval utilisation, not Ragas's rank-aware precision. The name is the
  parity name; the `limits` string says what it actually is, everywhere an admin reads it.
- No retrieval integration (an author supplies the chunks), no embedding similarity, no groundedness
  dashboard.
