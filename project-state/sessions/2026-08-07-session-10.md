§1 — observability/tracing parity with Langfuse, Helicone and LangSmith: a trace/span model over

The brief carried a correction from the previous wave that shaped the whole slice:

> Slice D was planned from a paragraph that was half wrong — its OpenAI-compatible endpoint already
> existed. Check the codebase before writing the brief.

So the premise was verified first, and it held: **no trace or span model anywhere in
`packages/db/src/schema.ts`, and no OpenTelemetry dependency in any package.json.**

## What the gap actually was

Not data. **Shape.**

Every fact a trace is made of already existed and was already governed: `orchestration_runs` plus
the node statuses in `state` (a DAG), `usage_events` (tokens, provider, model, measured cost),
`audit_log` (hash-chained, every governance decision including ADR-0066's fallback hops), guardrail
verdicts, eval runs, red-team trials, lineage nodes, workflow instances and stages.

What nothing in the product could say was: *this model call happened inside that node, which
happened inside that run; this tool call was asked for by that specific model turn; and the reason
there is no model call under this branch at all is that pillar 1 said no.*

## Decisions worth remembering

**1. The recorder WRAPS the dispatch attempt rather than being scattered through it, and that is
the argument, not a tidiness preference.** `dispatchOnce` was renamed `dispatchAttempt` and a thin
traced wrapper took its name. `dispatchAttempt` has about a dozen early returns — virtual-key
allow-list and budget, the MRM gate, the project budget, the §8.4 PII input block, the ADR-0042
guardrail input block, two egress refusals, a missing credential, an undispatchable agent — and
every one of them now lands as a `denied` span carrying its stated reason **without the core
mentioning tracing at all**. A thirteenth refusal added tomorrow cannot forget to be traced. If the
recorder had been sprinkled through the body instead, "a governance DENY is a present span" would
have been a convention somebody maintains rather than a property of the shape.

**2. A trace of only the successes would have been worthless, and the entitlement denial is the
one that nearly got missed.** Pillar 1's `evaluateAgent` refusal is decided at the ROUTE, before
the dispatch core is ever called — so wrapping the core covered every refusal except the most
common one in the product. It gets its own `policy` span, at `POST /v1/agents/:agentId/invoke` and
in the shared compat core, referencing the `audit_log` row just written. The test that catches this
asserts a span EXISTS, not merely that the API 403'd.

**3. A span references; it does not restate.** `usage_event_id`, `audit_log_id`, `run_id`,
`node_id`, `agent_id`. The one deliberate duplication is the five fields a tree must render without
an N+1 (`provider`, `model`, both token counts, `cost_usd`), copied FROM the referenced ledger row
in the same call — and the suite **joins the span back to `usage_events` by `usage_event_id` and
asserts every copied figure still agrees**, rather than trusting the copy. That test is what stops
a future "recompute the price from the rate card" refactor being invisible.

**4. `seq` exists because timestamps collide.** On an in-process path several spans share a
millisecond, and a tree whose children reorder between two reads is not a trace. Sibling order is a
monotonic per-trace counter allocated by the same atomic `UPDATE ... RETURNING span_count` that
maintains the list-view rollups — one statement doing two jobs. The unit tests give three siblings
identical start instants and require the order to hold, and to survive a shuffled input.

**5. Retention is the compliance cascade's, with NO new knob.** `runAuditPruneOnce` now deletes
traces under the same §8.3 floor it prunes `audit_log` under. A trace-specific dial would let an
operator keep prompts for a year under a framework whose cascade says ninety days — the exact drift
a cascade exists to prevent. The per-deploy-mode overrides are deliberately not applied to traces
(they key off `audit_log.deploy_mode`, which a trace has no equivalent of; the global floor is the
shorter and therefore safe direction).

**6. The OpenTelemetry SDK was rejected for a specific reason, not out of dependency aversion.** We
are not instrumenting a live process — we are serialising rows that are already in a database. The
SDK's value (context propagation, samplers, batch processors, auto-instrumentation) is entirely in
the part we do not need, while its cost lands squarely on an air-gapped-primary product: a
transitive dependency tree somebody has to review, and a background exporter whose whole design
assumption is that opening a socket is fine. The OTLP/HTTP JSON body is ~120 lines of pure
function, unit-tested against the spec's own constraints (32-hex trace ids, 16-hex span ids,
fixed64 nanoseconds as decimal **strings** — a Number loses precision above 2^53, which nanoseconds
pass in 1970).

**7. There is no default endpoint anywhere.** Not in the schema, not in the code, not in an env
var. With nothing configured the export route answers a real 409 whose detail says plainly that
this is the shipped state rather than a fault. When an admin types one it is adjudicated by the
ADR-0034/0043 egress guard at write time (a 400 that saves nothing) and again on every export.

**8. A DENY exports as OTel status ERROR, and that is a compromise recorded as one.** OTel's status
enum has exactly three members and none of them means "deliberately refused". `UNSET` would make a
governance refusal invisible in every off-the-shelf trace UI's error filter, which is the opposite
of the point. So `ERROR`, with `regulait.decision=denied` beside it — and the RegulAIt-side viewer
renders `DENIED` as its own word, because in somebody else's Grafana it will look like a failure.

## Adversarial verification

Eighteen gateway tests and twenty shared unit tests, each aimed at a way this feature can look
finished and be worthless:

- **A flat list relabelled.** A real orchestration run with a known shape (one node, a tool-using
  worker loop against a real local MCP upstream) is driven through the real endpoints, and the tree
  is asserted by **parent id and depth**: `run` → `run_node` → `llm` → `tool`, each child naming its
  actual parent's id, maxDepth ≥ 3, exactly one root. A recorder that wrote four siblings and let
  the UI indent by `kind` fails every line.
- **A cost the trace invented.** Joined back to `usage_events` by `usage_event_id`; cost, both token
  counts, model and provider all asserted equal, and equal again to the figure the CALLER was told.
- **A silent fallback.** A chain is configured, the primary is failed at the transport layer via the
  mock's `<<upstream-error:model>>` sentinel, and the serving hop is asserted to be a `fallback_hop`
  span whose `parentSpanId` IS the failed primary's span id.
- **A read surface that is default-allow.** Another user's trace id → 403. A non-admin listing
  somebody else's traces → **403, not a silently narrowed result set**.
- **An ordering that is "usually right".** Sibling order asserted on `seq`; the list endpoint's
  `startedAt DESC, id DESC` asserted pairwise across the page. (The brief named this hazard
  specifically: a list without an ORDER BY passed here for months once.)
- **A switch that is a comment.** Tracing off → the dispatch still succeeds, hands back no trace
  coordinates, and the trace count does not move. Content capture off → the tree, timings, costs and
  deny reasons all survive, and the prompt string appears **nowhere** in a dump of every span.
- **A tree builder that loses a branch.** Orphans (a parent outside the supplied set) are reattached
  at the root and FLAGGED, never dropped; a parent cycle terminates rather than recursing forever.

## Measured performance

On the dev box's Postgres 16, against a synthetic 2,000-span trace:

| Operation | Measured |
|---|---|
| Span rows written (single-row inserts) | 835 rows/s |
| Read ALL 2,000 spans of one trace | **42 ms, ONE query** |
| Assemble + flatten the tree (2,000 spans) | 7 ms |
| Encode 2,000 spans to OTLP JSON (2.6 MB) | 23 ms |

The recorder issues **two** statements per span (rollup/`seq` update, then insert), so its effective
throughput is ≈400 spans/s. A single dispatch adds four writes and one settings read, on a path
already waiting on a model provider over the network — but that is not free on a run fanning out to
hundreds of nodes, which is why the master switch writes nothing at all when off.

## What was NOT closed, and is disclosed rather than implied away

Twelve items in the ADR's "What this explicitly does NOT give you". The three that matter most:

1. **Connector calls, workflow stages and eval-run grouping are DECLARED span kinds with nothing
   writing them.** Adding each is a writer, not a migration — but today a trace of a connector call
   does not exist.
2. **Nothing has been verified against a live OTLP collector.** Same honesty line as ADR-0069's
   vendor presets. The encoder is spec-shaped and unit-tested; `dryRun: true` exists so an operator
   can read the exact body before sending it. The `gen_ai.input.messages` / `gen_ai.output.messages`
   content keys are an experimental part of the convention and older collectors expect
   `gen_ai.prompt` / `gen_ai.completion`.
3. **No prompt-playground diffing against a live trace** — named in the slice's own paragraph, not
   built. Also: no sampling and no per-project tracing policy (org-wide on/off only), no
   time-to-first-token (streaming is traced at completion), and the exporter is a pull with no
   spooling, no retry and no already-exported marker, so an overlapping re-run re-sends.

And the honest residual of the "tracing never fails the call it traces" rule: **a lost span is a
hole**. The read surface reports `partial: true` when the rollup and the stored spans disagree, and
the UI says so in words — but the span is gone.
