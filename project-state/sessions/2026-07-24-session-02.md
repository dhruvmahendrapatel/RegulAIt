## Gotchas worth remembering

- The container's root user can't run Postgres; tests ran with a cluster initdb'd/started as
  the `postgres` system user under `/var/lib/postgresql/regulait-pgdata`, port 55432
  (`DATABASE_URL=postgres://regulait@127.0.0.1:55432/regulait_test pnpm -r test`). This
  cluster is ephemeral to the remote session — recreate it next time.
- TS project references were removed from `apps/gateway/tsconfig.json` (would require
  `composite: true` everywhere); plain workspace deps + built dist are sufficient.
- Gateway integration tests are not idempotent against a dirty DB (unique email/server
  constraints) — drop/recreate `regulait_test` before rerunning.

## Later in the session (appended before session end — same session, not retro-editing)

- **PR #1 merged** (vertical slice + ADR-0009). **PR #2 merged**: CI workflow — build + tests
  on every PR/main push, Postgres 16 service container; first live run green in 54s.
- **MCP proxy path wired (PR #3)**: `POST /mcp/:serverId`, streamable-HTTP on both sides
  (SDK v1.29, stateless one-transport-per-request mode). `tools/list` syncs upstream manifest

  `reply.raw` 'close' + `closeAllConnections()` in test teardown; gateway vitest runs with
  `fileParallelism: false` (two test files share one DB).

- **Approvals + rate limits (PR #4)**: kernel `require_approval` effect + `ApprovalRule`/
  `RateLimit` inputs (pure — usage counts supplied by caller); order grants → deny → rate-limit →
  approval → allow. Migration 0001 (`approval_rules`, `rate_limits`, `approvals`); §6 Approvals
  Queue API (named-approver-only decides); proxy enforcement with pending-entry dedupe and
  atomic single-use consumption of approved entries. 41 tests total.
  Design choices: approval satisfied → single evaluation only (single-use); rate-limit usage =
  audit-log allow rows in window (counts /v1/evaluate dry-runs too — acceptable for slice);
  /v1/evaluate never creates/consumes queue entries (decision-only).

- **Data-scope rules (PR #5)**: kernel `DataScopeRule` (dot-path + allowed values, AND across
  matching rules, fail-closed on missing/non-scalar, denies before rate-limit/approval);
  migration 0002 (`data_scope_rules`); `POST /v1/rules/data-scopes`; proxy passes call args
  into `governedEvaluate`. §3 now feature-complete for the MCP object type. 49 tests.
  Values compared as strings (`String(value)` vs the string allow-list) — numeric/boolean args
  work but e.g. "5" matches 5; revisit if type-strict matching is ever needed.
