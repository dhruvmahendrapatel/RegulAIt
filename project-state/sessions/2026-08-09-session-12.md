# Session 12 — 2026-08-09 — giving the parity features a user-facing surface

*Append-only. Never edited retroactively.*

## What this session was

The owner's second request was competitor-parity functionality and *"maybe we will release this as
a freeware."* Six parity ADRs shipped in session 11's wave, but **three of them disclosed, in their
own "what this does NOT give you" sections, that there was no SPA page**. On a freeware tool that
means nobody can use the feature without `curl`, so from a user's point of view it is not built.

This session is a **UI slice over already-accepted decisions**. By instruction and by judgement it
wrote **no new ADR and no migration** — instead it appended **dated amendments** to ADR-0066,
ADR-0069, ADR-0071 and ADR-0072 recording that a stated gap is now closed. The Accepted text of all
four is untouched; the amendments sit below a `---` and say so explicitly.

## What shipped

**`/admin/virtual-keys`** (ADR-0066, nav *Identity & Access*, beside Client access) — issue a key
with owner / allow-list / lifetime budget / expiry / pinned platform credential; the plaintext token
is shown **exactly once** through the existing `RevealCard`; the page has no field for a token and
never fetches one after issuance. The ceiling leads the page: *a key only ever NARROWS*, with the
three-clause allow rule and the sentence *a key issued by an admin is not an admin*. `spentUsd` (the
enforcement counter the 402 is computed from) and the `usage_events` total are rendered **apart**,
with the disagreement case stated in words. Revoke is confirmed and never deletes.

**`/admin/cost-consolidation`** (ADR-0069, nav *Cost & Optimization*, under Cost dashboard) — upload
or paste an export, pick an adapter, read that adapter's `limits` string **verbatim from the
registry**, dry-run (parsed / accepted / **refused with file line numbers**), apply, revoke a batch
with an audited reason. Plus the identity-mapping surface (alias / domain rule / per-person cost
centre) and the consolidated per-person and per-cost-centre view with per-vendor staleness.

**Shadow-AI raw import** (ADR-0071) — an addition to the existing page, not a second page, mirroring
the structural claim the ADR makes about the routes. Adapter selection, each adapter's
`verification` sentence **verbatim**, the `formatBasis` badge, the refuse-whole-file default with
its opt-out labelled as an opt-out, refusals naming their line, and the full adapter registry table.

**ADR-0072's stranded-baseline report** on `/admin/evals` — versions, per-version run counts labelled
comparable / NOT comparable, the changelog of what a score MEANT, and every stranded pinned baseline
by run id with the action to take.

**ADR-0067 needed no work.** Its four groundedness scorers come from the registry and its
`eval_cases.context` field was already authorable — verified in a browser rather than assumed.

## The rule that shaped the cost page

ADR-0069's whole point is that `metered` (we saw the call) and `imported` (we were told) are two
different kinds of number and are never added. The API has no field for a blend, so the page has no
cell for one: two separately-ruled columns, each printing its own basis word and what that word
means, with the subject's `coverage` sentence underneath. The browser spec **computes** each
subject's `metered + imported` from the API's own answer and asserts that number appears nowhere in
the rendered document — so the guarantee cannot quietly stop being tested if the seeded metered
spend moves. Unattributed spend is its own visible subject and is never spread pro-rata.

## Two real bugs found only by driving a browser

Both are the kind a unit test would not have caught, and both are in shared code, so they were
degrading every admin surface, not just the new ones.

1. **`apps/web/src/api/client.ts` crashed while formatting a refusal.** `errDetails` called
   `.join(".")` on `issues[].path`, but the gateway sends that path **already joined into a string**
   (`path: i.path.join(".")`). The TypeError escaped from the `ApiError` constructor, so the operator
   saw `(o.path ?? []).join is not a function` instead of the reason the platform gave. That is
   precisely the failure the "honest refusals surface as honest UI" rule exists to prevent. Fixed to
   accept both spellings, with the type widened to say both are real.
2. **`RequireAdmin` silently bounced a non-admin to Home.** A disappearance is not a refusal: the
   person who typed the URL could not tell "I am not allowed" from "that page does not exist". It now
   renders a real statement, with a note that the server refuses these endpoints independently.

Also: `.statRow` (admin.module.css) and `.grid` (views.module.css) were referenced by roughly fifteen
admin screens and **never defined**, so those stat rows had no layout at all. Both are now defined
once rather than edited at fifteen call sites.

One a11y fix fell out of the browser work: the cost page had two inputs both labelled "Reason", which
was ambiguous to a screen reader as well as to Playwright. They are now distinct.

## Disclosed rather than closed

- **ADR-0066's fallback chains still have no page.** Virtual keys got one; chains did not.
- **Adapter configuration is a raw JSON textarea**, not a per-adapter form builder. The page states
  what each adapter requires, but a typo in the JSON is caught by the gateway, not by the form.
- **No bulk cost-centre editor** — one person at a time.
- **The evidence adapters have still never met a real vendor export.** The page makes that visible;
  it does not make it untrue. Same for ADR-0069's three declared-header vendor presets.
- **Card titles are not headings.** The admin console's `Card` renders its title as a `div`, and a
  clickable table row is given `role="link"`. Both are pre-existing house conventions that this
  slice followed rather than changed, because changing them would move assertions in every existing
  e2e spec. They are worth revisiting as their own piece of work.
- The e2e suite now waits out the ADR-0031 login rate limit rather than raising it. A test run that
  only passes because a security control was weakened for it is not a passing test run.
