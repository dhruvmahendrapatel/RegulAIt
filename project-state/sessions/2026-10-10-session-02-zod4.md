# 2026-10-10 — session 02: zod 4 upgrade (ADR-0192)

**Brief:** zod was pinned at 3.25.76, the last 3.x release (2025-07-08), which fails ADR-0176's maintenance rule.
Assess the move to 4.x and carry it out if it is tractable.

**Outcome:** done in one PR on `dhruv/awesome-shannon-gk4cp2`. ADR-0192 records the decision and every behaviour
change.

## What changed
- All ten zod-using packages are pinned to `4.6.5`. The lockfile was updated through `pnpm install`.
  `zod-to-json-schema` was removed and the gateway OpenAPI bodies use `z.toJSONSchema` (`io: "input"`).
- 47 single-argument `z.record` calls now take a `z.string()` key schema.
- Two enum-keyed records (BOM `renderings`, org `modeAuditRetention`) became `z.partialRecord`. Without it, zod 4
  would have required every key.
- Defaults inside optional fields: the builder skill PATCH would have reset `description` to `""`, and rubric criteria
  would have gained defaults they never set. Both are now built from default-free fields. A runtime walker over every
  exported schema found no other case.
- Type-only fixes: five `uniqueBy` refine callbacks, and one symbol path segment.
- Tests: non-RFC uuid fixtures were rewritten only in failing files (3 shared, 20 gateway). One golden decision-regression
  reason was updated for zod's new message text. One test that read 3.x internals now reads `.shape`. OpenAPI
  artifacts were re-rendered.
- THIRD_PARTY: `packages/shared/THIRD_PARTY.md` had no zod row, contrary to the brief, so one was added. The three
  engine THIRD_PARTY rows now say 4.6.5.

## Verification
- `pnpm -r build` is clean. shared: 2267/2267. Other zod packages: all green.
- Gateway, 4 local shards on fresh databases: 5333 passed and 9 skipped (S3, no object store here), with 1 failure.
  The failure was the `zz-b4o-outbound-audience` timing ratio (8.9 against a limit of 8) under four-shard CPU
  contention. That path does not use zod. The test passed 3/3 unloaded on the same commit (e54b3bbc) and passed in the
  first full run.
- `demo:prepare`: 19 pass, 0 fail, with the demo export key set as `demo:export-key` instructs.
- A leak probe confirmed that zod 4 issues carry no input values. 3.x enum issues did carry them. Object key names
  still appear in `unrecognized_keys`, as in 3.x.

## Process note
- My wait loops used `pgrep -f "<pattern>"` with a pattern that also appeared in their own command lines, so they
  never exited. I stopped them by PID (M-073 holds). Wait on a recorded PID, not a pattern.
