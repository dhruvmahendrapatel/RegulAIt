## Finding C611-01 — MEDIUM: model drafting cannot run with strict project attribution

Location: `apps/gateway/src/agent-setup-assist.ts:95` (with request-schema constraint at `packages/shared/src/agent-setup-assist.ts:18`).

The model path unconditionally passes `projectId: null` into `executeGovernedDispatch`. This invokes `attributionDispatchGate`, which requires a project under the default `dispatchAttributionRequired=true` setting and returns `attribution_required` before provider work. The assistant request schema is strict and contains no project field, and its UI contains no project picker. Thus even an entitled admin using an enabled agent cannot satisfy the refusal's advice to resend with a project. The only workaround is relaxing the organisation-wide attribution security control, losing project budget/cascade scoping for this request. Existing feature tests hide this by setting `dispatchAttributionRequired:false` at fixture setup (line 66).

Fix: add an explicit authorized project selection to request and UI, verify the caller's project membership through the standard path, and pass that ID to governed dispatch. Preserve attribution, project budget, PII and use-case gates. Add a regression that leaves attribution enabled and exercises a valid project plus an unauthorized project's refusal.
