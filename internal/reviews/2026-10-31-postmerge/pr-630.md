## A2A-SEC-01 — MEDIUM: a redirect can reflect the stored upstream credential to a non-admin caller and into the audit trail

Location: apps/gateway/src/a2a.ts:355-362 (especially `const reason = blocked ?? ...`, storing reason at360 and returning it at362). Underlying helper apps/gateway/src/egress-guard.ts:679-683,697-701 interpolates raw upstream Location into EgressRedirectError and exposes it through egressRefusal.

The A2A error handler correctly replaces ordinary remote errors with a fixed sentence, but treats any egressRefusal string as safe local diagnostic text. Redirect Location is supplied by the upstream, not by this gateway. An agent that reflects its Authorization token into a redirect URL makes the gateway return that token verbatim to the calling user's API key, even though that user cannot read the admin-only stored credential. The same raw secret is persisted in audit_log.reason. An upstream failure does not need to be a successful agent message to cross this boundary.

Proof: copied the existing A2A integration suite outside the checkout. Changed only the redirect target to include the synthetic upstream SECRET and added `expect(r.body).not.toContain(SECRET)`. Existing credential setup is admin-only; the request uses the ordinary granted user's key. The regression fails with 502 detail containing `.../rpc?credential=<synthetic stored secret>`. The credential was not forwarded to the redirect destination, so the SSRF defense holds; its reflection through the error response does not. A boolean/count-only SQL check found one a2a-upstream-error audit row whose reason contained the synthetic secret. No secret values are included in this report.

Fix: distinguish redirect refusals from locally generated policy decisions. For a redirect, return and audit a fixed reason such as “the upstream returned a redirect; redirects are refused,” with a bounded reason code, and do not include Location, upstream body, or exception message. Add the regression above to the real suite, asserting both HTTP response and persisted audit omit the credential.

## A2A-SEC-02 — MEDIUM: upstream JSON is unbounded before the SDK parses it

Location: apps/gateway/src/a2a.ts:172-188 (`agentFetch` passes the upstream Response through unchanged); card resolver call at214 and SDK call344-353. The card's60,000-byte check at151 occurs after SDK JSON parsing and normalization; reply truncation at259/262 likewise occurs after the whole JSON response has been buffered, parsed and converted.

A compromised or broken registered endpoint can supply an arbitrarily large card or message/error payload. The shared guarded fetch adds a60-second deadline but no response/decompressed-byte limit; pinned-fetch streams the body and decompresses gzip/deflate/brotli without a limit. JSON parsing and protobuf conversion therefore allocate proportional to attacker-chosen response size and run synchronously before either local cap has any effect. The60k card constant is explicitly a normalized/stored-card bound, not a raw transport bound; that storage bound works, but does not protect the new remote JSON ingress.

Safe bounded proof (no OOM/stress test): /workspace/.setup/reviews/630-sdk-body-probe.mjs uses the exact pinned SDK and streaming Response objects. A2,097,516-byte card containing a2MiB unknown field was fully consumed and normalized to329 bytes; the actual exported cardProblem accepted it (`null`). A2,097,261-byte JSON-RPC reply was fully consumed and its2,097,152-character text parsed before a64,000-character output slice could run. Source inspection confirms agentFetch has no additional limiter. No huge payloads or exhaustion attempts were run.

Fix: wrap A2A's guarded Response stream in a bounded reader before passing it to the SDK, reject/cancel once decoded bytes exceed an explicit card/RPC/error budget, and treat oversize as an audited upstream failure without charging. Test chunked payloads without Content-Length, gzip expansion, unknown JSON fields, oversized text and oversized non-2xx error bodies. Do not rely only on Content-Length or normalized-object size.
