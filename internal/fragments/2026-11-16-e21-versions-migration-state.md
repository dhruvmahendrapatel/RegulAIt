**2026-11-16 - E21 slice 3: workflow template versions, pinning, canary and governed in-flight migration ([ADR-0340](../decisions/0340-workflow-process-reliability.md) decisions 11-14, lane E21, migration `pending/workflow_template_versions.sql` numbered at merge).** `workflow_template` is now an ADR-0048 config-version type (immutable versions, activation ledger, rollback, a LIVE canary over a share of new instances, sticky per instance id). Each instance records the versions that served it (`workflow_instance_template_versions`) and runs them to the end. A running instance moves only through `POST /v1/workflows/instances/:id/migrations`: a dry run returns the kernel's plan and an RFC 6902 diff, and a filed request goes to the one approvals queue (`workflow_migration`) for another admin. On approval it is re-planned under the instance lock and applied, or recorded stale. Two API-only routes are tracked on #453.
