## The finding that mattered most

The feature was the smaller half. Building an egress guard for the *new* `baseUrl` surface forced
an audit of the old ones, and the disclosure in ADR-0034 undersold what was there:

**`POST /v1/users/:userId/model-credentials` is in `NON_ADMIN_ROUTES`.** Not admin-only. And a
per-user credential takes **precedence** over the platform one at dispatch. So:

1. any authenticated user sets their own credential's base URL to
   `http://169.254.169.254/latest/meta-data/iam/security-credentials/`
2. next dispatch of any agent for that provider
3. the gateway fetches it and returns **this EC2 instance's IAM role credentials**

Live since per-user BYO keys shipped (migrations 0016/0017). Not a new-feature risk — a
pre-existing one the new feature's review happened to surface.

**Generalisable lesson: when you build a control for a new instance of a pattern, audit the old
instances in the same pass.** The guard and the hole were the same shape; only one had been
noticed.

## The exfiltration case, and why the test is shaped as it is

`connectors.baseUrl` mattered more than the SSRF reading suggested. The `webhook` connector kind
does not *read* its URL — it **POSTs the caller's payload** to it. A governed connector call is
exactly where customer data lives. So an admin-typed URL was a governed, audited, cost-attributed
pipe to an attacker's collector.

The test proves closure by **absence**, which is the only proof that means anything here: stand up
a live, listening, willing collector on un-allow-listed loopback; insert a pre-guard `webhook` row
straight into Postgres pointing at it; invoke with a canary payload. Assert the collector received
**zero requests** and never saw the canary — not merely that the API returned 403.

## Three PRs disclosed the DNS-rebind window before one closed it

Each of #95, #96 and #98 wrote down that the https rebind TOCTOU was open and did not close it.
That was the right call each time — the fix was a dependency decision, not a line of code — but it
is worth noting that the honesty is what made #100 possible: the residual was recorded precisely
enough to be picked up later without re-deriving it.

**The dependency decision came out NO NEW DEPENDENCY.** Node 22 exports no `undici` module and no
`Agent`. The two routes to one were a direct `undici` dependency (a second, independently-versioned
HTTP stack **in the security path**) or `globalThis[Symbol.for("undici.globalDispatcher.1")]` (an
undocumented internal that can vanish in a patch release, silently, in the code that decides where
our sockets go). Neither survives the posture `ci.yml` already states for `dorny/paths-filter`.
`http.request`'s documented `lookup` option gives the whole capability from stdlib for ~300 lines.

**The test performs the attack** rather than asserting the happy path: two real TLS listeners bound
to `127.0.0.1` and `127.0.0.2` on the same port, a resolver stub answering benign-then-attacker.
Unpinned, the socket lands on the attacker's listener while the guard's verdict says otherwise —
asserted on `res.socket.remoteAddress`. Pinned, the attacker records zero connections and the
resolver is called exactly once.

A subtle trap found on the way: `Agent.getName()` does not include `lookup`, so a shared agent
would hand a request pinned to address A a pooled socket already open to B — **silently undoing the
pin**. Named regression test.

## Backup: merged is not running

ADR-0035 is merged. **It is inert.** The bucket, the IAM grant and the systemd timer do not exist
until `terraform apply` plus a one-time SSM install, and the SSO session expired before either
could be done. **The database still has no backup as of this writing.** Tracked separately so it
cannot hide behind a green checkmark.

Two things from it worth keeping regardless:

- **`pg_restore --list` exits 0 on a 90%-truncated dump that restores 0 of 200,000 rows.** The
  obvious verification would have blessed and uploaded a backup containing none of the data. The
  expensive full parse is load-bearing, and this was *measured*, not assumed.
- **`REGULAIT_DATA_KEY` is deliberately not in the bucket** — storing it beside the ciphertext it
  protects defeats the envelope split. So a restore onto a *new* box recovers every row and leaves
  every credential permanently undecryptable. Recording it out-of-band is the top follow-up.

## HSTS: the ADR's premise expired, and its reasoning had a flaw

ADR-0029 argued HSTS off because the hostname derives from an IP that can change. ADR-0032's
Elastic IP changed that premise this same day. But the ADR also **overstated its case**:
`includeSubDomains` on `<dashed-ip>.sslip.io` was called "hostile to everyone else using sslip.io",
and it is not — HSTS is host-scoped, so it covers `*.<that name>` only. Corrected on the record.

The better argument, which the ADR did not make: a released Elastic IP **returns to the AWS pool**,
so a stranger could inherit our hostname *and* whatever pin we left in visitors' browsers. That
externality outlives our eventual move to a real domain; a short `max-age` is what bounds it.

Also worth recording as a **limit on the "admins get a toggle for everything" mandate**: HSTS was
deliberately NOT made an `org_settings` toggle. It is a deployment-shape fact an admin cannot judge
from a portal; it is the one setting a server **cannot undo** once a browser stores it; and it is
read in the `onSend` hook that must work when Postgres is down. The mandate asks for options where
a choice is feasible — not for a non-revocable client-side commitment behind a self-service button.
