# 2026-09-30 Session 04: MCP Redacted Actions

## Scope and Outcome

Continued the owner's active P1/P2/P3 and Credo-parity implementation goal.
ADR-0143 and migration 0120 are this chapter's additions. Public redaction is
still deliberately unavailable; this is a tested MCP integration, not a claim
that model/connector/streaming redaction or the parity programme is complete.

The MCP registry retains admitted input schemas. Prepared actions validate
against a strict, self-contained draft-07 schema, bind original/effective
digests, transformation policy and schema identity, and force action scope.
Both payload forms satisfy data scopes. Queue previews and captured input
traces contain only the effective action; failed preparation captures none.
Schema/policy changes during connection refuse without consuming consent.
The immutable effective payload is sent once; text/structured results are
redacted, opaque content is withheld, and completed calls are still metered.
Upstream error messages are sanitized under redaction.

Policy-generation triggers cover PII sources, grants/scopes/guardrails and
actual tool schema/kind/halt changes. They supplement the existing approval
and ABAC triggers. No network operation runs inside an approval transaction.
An unchanged tool upsert does not advance its epoch. Discovery that adds a
schema requires fresh evaluation before a redacted call may proceed.
