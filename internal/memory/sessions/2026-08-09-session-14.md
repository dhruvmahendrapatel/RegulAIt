# Session 14 — 2026-08-09 — Closing out: surfaces, ADR-0073, and the final validation

Append-only. Never edited retroactively.

## What was asked for

Three phases, run in order, each verified on a freshly created database by the main session rather
than by re-reading an agent's report.

## Phase 1 — the parity features get a user-facing surface

Three of the six parity ADRs had shipped **API-only**. For a tool the owner may release as
freeware, that is not built: nobody can use a feature that requires curl. An audit found virtual
keys (0066) and cross-vendor cost consolidation (0069) had no page at all, and ADR-0071's raw
evidence import was not wired into the existing shadow-AI page.

Closed with no new ADR and no migration — dated amendments to 0066/0069/0071/0072 instead.

**Driving a real browser found two bugs every unit test had missed**, and both were on *every*
admin surface, not just the new pages:

1. `apps/web/src/api/client.ts` called `.join(".")` on a `path` the gateway had **already joined
   into a string**. The TypeError escaped the `ApiError` constructor, so an operator saw
   `(o.path ?? []).join is not a function` **instead of the refusal reason** — precisely the
   failure the honest-refusal rule exists to prevent.
2. `RequireAdmin` silently redirected non-admins to Home. **A disappearance is not a refusal.**

Also: `.statRow` and `.grid` were referenced by ~15 admin screens and **never defined** in either
stylesheet.

The lesson is narrow and worth keeping: **a viewing feature that has never been opened is not
verified.** Six waves of green suites did not surface any of these.

## Phase 2 — ADR-0073, and a brief that was wrong

Task #121, open since the ADR-0048 wave, was the project's longest-standing declared gap: rule and
compliance-profile versions stored, activated and rolled back, but the kernels still read their own
tables, so the shadow canary evaluated nothing.

**The brief instructed the agent to flip `canaryIsLive` true for rules. That instruction was
wrong.** `canaryIsLive` means *"does the canary SERVE traffic?"* — flipping it would make a
candidate version **enforce a deny on a percentage of real work**, violating the "a shadow canary
must NEVER affect the served decision" invariant stated in the same brief. It would have closed the
gap by breaking the thing the gap protected.

The agent declined that instruction and fixed the real bug, which was the **conflation**:

- `canaryIsLive` — does it serve? **False for rules, permanently, pinned by a test.**
- `canaryIsEvaluated` — does it produce a signal? **Now true** for all four rule types.
- `canaryModeOf` → `live | shadow | inert`.

That is a better answer than the one asked for. Recording it because the failure was mine: a brief
can contain a contradiction, and an agent that follows both halves ships an outage.

`agent_config` now honestly reports `inert` after claiming `live` for two waves.

## The thing this session should be judged on

Across the whole arc, **three scoring inversions** were found and fixed, and the third was created
by the fix for the first two:

1. ADR-0044 scored a missing judge as 0 — a missing instrument recorded as a bad measurement.
2. ADR-0057 scored a guardrail-BLOCKED dispatch as a DEFEAT — defences working looked identical to
   defences failing.
3. **ADR-0072's own classifier was a deny-list**, so any unrecognised code counted as
   `governance_stop`: *fully resisted, the defence worked*. A fail-open in a security metric.

Inverting (3) to an allow-list immediately caught two things it had been hiding: a **real** code
missing from the list (`agent_not_entitled`), and an assertion in ADR-0072's own test about a code
**nothing emits** (`egress_not_allowed`) that had been passing vacuously. A test can be green for
the wrong reason, and only a fail-safe default exposes it.

## Standing, and not resolvable here

**No model provider is connected** — the owner's key is parked by standing instruction and was not
requested. Judge grading, red-team probe grading, the four remote training adapters, the three
cost-import vendor presets, the OTLP collector and every evidence-format adapter remain
**mechanism-proven and instrument-unverified**: the plumbing is tested end-to-end against real
Postgres and real HTTP; the *judgement* is not observed. Connecting one provider key is the single
change that would convert the most capabilities from partial to verified.

Also unchanged: no SOC 2 / ISO certification and no HA. Neither is a code problem, and both are
where deals are actually lost.

## Open, ordered by what bites first

1. **Rule-CRUD routes do not mint a version** (ADR-0073) — a versioned rule edited through the old
   surface has its row and its active version disagree, and dispatch keeps serving the version.
2. ADR-0070's `connector` / `workflow_stage` / `eval_case` span kinds are declared with nothing
   writing them; a DENY exports as OTel status ERROR, so elsewhere a refusal looks like a failure.
3. ADR-0069 overlapping CUR chunks double-count; ADR-0066 fallback chains have no page.
4. ADR-0072 has no down migration and its semantics version is global rather than per-dataset.
5. Foot-gun: the red-team scheduled sweep has no `trials` override and inherits the pair's last
   run, so a one-off 25-trial investigation costs 25× on every subsequent sweep.
