# Third-party runtime dependencies added deliberately

One line per dependency added under the owner's direction (2026-10-05) to prefer proven, permissively
licensed open source over hand-written code for standard problems. Each works offline (no runtime
network calls), so an air-gapped deployment is unaffected.

| Package | Version | Licence | Why |
|---|---|---|---|
| `standardwebhooks` | 1.1.1 | MIT | Signs outbound webhooks per the Standard Webhooks specification (`webhook-id`, `webhook-timestamp`, `webhook-signature`, `whsec_` secrets), so receivers verify with any off-the-shelf library (ADR-0173 batch 2b). Its transitive dependencies are `@stablelib/base64` 1.0.1 (MIT) and `fast-sha256` 1.3.0 (Unlicense, a public-domain dedication). |
| `diff` | 9.0.0 | BSD-3-Clause | Line diff of two prompt-registry commits' templates (ADR-0173 batch 2b). No dependencies. |
| `re2js` | 2.8.6 | MIT | Linear-time regular expressions (a pure-JavaScript port of RE2) as Ajv's `code.regExp` engine, so a user-supplied JSON Schema `pattern` / `patternProperties` in the playground or a prompt commit cannot stall the event loop (ReDoS), ADR-0173 batch 2b. No dependencies, no install script, no native build and no runtime download; the native `re2` binding was rejected because its install downloads a prebuilt binary (or compiles one), and `re2-wasm` has had no release since 2022. |
| `jose` | 6.2.12 | MIT | Verifies the Teams Bot Framework's Bearer JWT (`jwtVerify`) against the JWKS named by the workspace's OpenID metadata (`createRemoteJWKSet`, with its key-set cache and unknown-key refresh), ADR-0173 batch 2b. Already in the lockfile through `openid-client`; now a direct, exact-pinned dependency. No dependencies. Its only network use is the key-set fetch, which goes through our egress-guarded fetch (`customFetch`), so with no allow entry it makes no call. |
| `simple-statistics` | 7.12.1 | ISC | TEST-ONLY (devDependency): the oracle the KRI percentile test checks Postgres `percentile_cont` against (`quantile`, linear interpolation), ADR-0173 batch 2c. Nothing at run time: production percentiles are computed by Postgres. No dependencies. |
| `csv-stringify` (via `@regulait/shared`, not a direct dependency) | 6.9.0 | MIT | Formats each row of the audit-log CSV export (`GET /v1/audit.csv`) and the annotation-queue export through the shared `csvRecord`, with `escape_formulas` (OWASP CSV injection), replacing two hand-written escapers (ADR-0173 batch 2c fix round A). The streaming loop stays `csv-export.ts`. No dependencies. |
| `otpauth` | 9.5.2 | MIT | TOTP code generation and the per-step constant-time check (`HOTP.generate`, `HOTP.validate`), the step counter (`TOTP.counter`) and base32 secrets (`Secret`), replacing the hand-written RFC 4226/6238 and base32 code in `totp.ts` (ADR-0183 batch 2.1, ADR-0181 follow-up). RegulAIt keeps only the ±1-step window, the replay rule and the byte-exact enrolment URI. Its one dependency is `@noble/hashes` 2.4.0 (MIT); under Node it uses `node:crypto` for the HMAC. No install script, no runtime download. Latest release 2026-09 (maintained). |
| `@opentelemetry/sdk-metrics` | 2.12.0 | Apache-2.0 | The meter behind `/metrics` (ADR-0185 G5): counters, histograms and gauges, per-instrument Views that drop any attribute key not on the instrument's list (`createAllowListAttributesProcessor`) and cap each instrument at 500 series (`aggregationCardinalityLimit`). Chosen over `prom-client`, which has had no release since 2024-06 (ADR-0176 maintenance test). Released 2026-10-06. Its dependencies are `@opentelemetry/core` 2.12.0 and `@opentelemetry/resources` 2.12.0 (Apache-2.0), and `@opentelemetry/semantic-conventions` 1.43.0 (Apache-2.0, already locked). No install script, no runtime network use. |
| `@opentelemetry/exporter-prometheus` | 0.223.0 | Apache-2.0 | The Prometheus text exposition for `/metrics` (ADR-0185 G5). Constructed with `preventServerStart: true`, so it never opens a socket: RegulAIt's own listener checks the bearer token and then calls the exporter's `getMetricsRequestHandler`; the main-listener route uses its `PrometheusSerializer`. `withoutTargetInfo` and `withoutScopeInfo` keep resource and scope labels out of every series. Released 2026-10-06. No install script, no runtime network use. |
| `@opentelemetry/api` | 1.9.1 | Apache-2.0 | The instrument types the meter returns (`Counter`, `Histogram`, `Gauge`), and the peer dependency both packages above require. Already in the lockfile; now a direct, exact-pinned dependency. No dependencies. |
| `@simplewebauthn/server` | 14.0.3 | MIT | WebAuthn registration and assertion verification for passkeys, step-up and passkey-signed approvals (ADR-0186 A/B): `generateRegistrationOptions`, `verifyRegistrationResponse`, `generateAuthenticationOptions`, `verifyAuthenticationResponse` (COSE keys, signature counters, user verification, RP ID and origin checks), instead of hand-written CBOR/COSE/attestation code. Released 2026-09-25. Transitive (all MIT unless stated): `@peculiar/x509` 2.1.0, `@peculiar/asn1-schema`, `-x509`, `-x509-attr`, `-x509-post-quantum`, `-ecc`, `-rsa`, `-android`, `-cms`, `-csr`, `-pkcs8`, `-pkcs9`, `-pfx`, `-asym-key` 2.10.0, `@peculiar/utils` 2.0.3, `tsyringe` 4.10.0, `@hexagon/base64` 1.1.28, `@levischuck/tiny-cbor` 0.2.11, `pvtsutils` 1.3.6; `reflect-metadata` 0.2.2 (Apache-2.0); `tslib` 1.14.1 / 2.8.1 (0BSD, already locked). No install script, no native build. **Air-gap note, binding on slice A:** the library makes no network call on the passkey path we use, but VERIFYING a certificate-bearing attestation (`packed`/`tpm`/`android-key`… with `x5c`) fetches the CRL URLs named inside the attacker-supplied certificate (`helpers/isCertRevoked.js`, plain `fetch`, outside our egress guard), and `MetadataService` downloads the FIDO MDS blob if initialised. So registration requests `attestationType: "none"` and refuses any response whose attestation format is not `none` before calling `verifyRegistrationResponse`, and `MetadataService` is never initialised. |
| `pkijs` | 3.4.1 | BSD-3-Clause | RFC 3161 trusted timestamps on audit anchors (ADR-0186 S): builds the `TimeStampReq` and parses and verifies the `TimeStampResp` / CMS `SignedData` (message imprint, nonce, ESS signing-certificate binding, chain to the configured trust bundle, timeStamping EKU), instead of hand-written ASN.1. Released 2026-09-20. Transitive: `bytestreamjs` 2.0.1 (BSD-3-Clause), `pvutils` 1.2.0 (MIT), `pvtsutils` 1.3.6 (MIT), `@noble/hashes` 1.8.0 (MIT), `tslib` (0BSD). Pure JavaScript; no network of its own (the TSA request goes through our egress-guarded fetch). |
| `asn1js` | 3.0.10 | BSD-3-Clause | The ASN.1 BER/DER codec under `pkijs`, pinned as a direct dependency at the version `pkijs` resolves so the two cannot drift (ADR-0186 S). Released 2026-04-20. Transitive: `pvtsutils`, `pvutils` (MIT), `tslib` (0BSD). |
| `write-file-atomic` (via `@regulait/engine-runner`, not a direct dependency) | 8.0.0 | ISC | ADR-0187 B5-M (PR #212 review [4234946106]): the gateway now imports the runner core's `fsyncDir` so the model-artifact filesystem store fsyncs the directory after its rename and every directory it newly created; that makes `@regulait/engine-runner` a runtime dependency of the gateway and brings its one dependency, `write-file-atomic` (npm's own, with `signal-exit` 4.1.0, ISC), into the image. Already locked and admitted in `packages/engine-runner/THIRD_PARTY.md`. No install script, no runtime download. |
